# Predicting Loss-Making Retail Transactions

**Week 4 Task — Machine Learning Model Development and Evaluation**
(Yuva Intern / NSDC internship program)

A binary classification model that predicts, using only order-time
information (category, region, segment, quantity, discount, sales),
whether a retail transaction will end up loss-making. Builds on the
exploratory analysis (Week 2) and hypothesis testing (Week 3) done
earlier in this internship on the same dataset.

## Results Summary

| Model | Test Accuracy | Precision | Recall | F1 | Test ROC-AUC | 5-fold CV AUC |
|---|---|---|---|---|---|---|
| **Logistic Regression (selected)** | 91.7% | 0.939 | 0.762 | 0.842 | **0.970** | 0.969 ± 0.003 |
| Decision Tree (depth=4) | 91.6% | 0.933 | 0.762 | 0.839 | 0.958 | 0.957 ± 0.004 |
| Decision Tree (unconstrained) | 88.2% | 0.796 | 0.793 | 0.795 | 0.855 | 0.848 ± 0.007 |

Logistic Regression was selected as the final model: best test-set
performance, fully interpretable coefficients, and — unlike the
unconstrained decision tree (100% train accuracy, only 88.2% test
accuracy) — no sign of overfitting.

## How to Run (VS Code)

1. Open this folder in VS Code (`File > Open Folder`).
2. Create and activate a virtual environment:
   ```bash
   python -m venv .venv
   # Windows:
   .venv\Scripts\activate
   # macOS/Linux:
   source .venv/bin/activate
   ```
3. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```
4. Run the full pipeline:
   ```bash
   python main.py
   ```
   This regenerates `data/retail_data.csv`, trains all three models, prints
   evaluation metrics to the console, and writes `outputs/metrics.json` plus
   5 figures to `outputs/figures/`.

(The Word report itself was generated with a Node.js script using the
`docx` package — optional to re-run; the finished `.docx` is already
included under `outputs/`.)

## Methodology Overview

1. **Data preparation** — stratified 75/25 train/test split; numeric
   features standardized, categorical features one-hot encoded, all
   inside a single `sklearn.Pipeline` to prevent data leakage.
2. **Model selection** — Logistic Regression (primary/interpretable
   baseline), a depth-limited Decision Tree, and a deliberately
   unconstrained Decision Tree (to illustrate overfitting).
3. **Evaluation** — accuracy, precision, recall, F1, ROC-AUC, 5-fold
   cross-validated AUC, confusion matrix, ROC curve, precision-recall
   curve, feature coefficients, and a train-vs-test accuracy comparison.
4. **Critical discussion** — error analysis (false negative cost),
   class imbalance handling, and concrete next steps (threshold tuning,
   additional features, regularization search, ensemble methods).

Full narrative, all visualizations, and the complete critical discussion
are in `outputs/Week4_ML_Model_Development_Evaluation_Report.docx`.
